# AgentMind V1.0.0 — draft, unreleased

**NO-GO. No publication authorization.** This draft describes the intended product and the evidence limits, not a released version. The source candidate is still version 0.0.1. A reviewed version change and exact-artifact recertification are required before V1.0.0 notes can become final.

AgentMind is a local-first, project-scoped memory, continuous-learning and immutable Agent Skills platform shared by coding-agent integrations. TypeScript/Node.js, SQLite/FTS5 and a shared core avoid per-provider knowledge stores or additional model APIs.

- Shared memory/experiences retain project scope and lower-trust source assertions.

- Distribution/rollback/recovery tests use disposable synthetic authorization and owned destinations; they do not establish protected deployment.
- SQLite schema11 migrations, FTS5, process concurrency, WAL-aware backups and restore to a new offline path are exercised using synthetic fixtures. Process kill tests do not prove power-loss durability.

## Security profile limits

Actual OS-separated authority remains NOT VERIFIED. Ordinary local-owner mode is supervised; unrestricted same-UID code may access owner files/SQLite or simulate a PTY. Protected approval requires independently verified identities, permissions, broker peer authority and exact grants. It is not provisioned by setup.

Actual BE-001 sandbox isolation remains NOT VERIFIED, with no accepted executable backend. Behavioral execution refuses rather than running untrusted candidate scripts on the host. Static PASS and model-reported success are not trusted behavioral evidence. No automatic approval, promotion or distribution is enabled.

Local-first does not mean all coding-CLI communication stays local. Provider model behavior/authentication is external. Redaction is heuristic; canonical legacy data and all-project backups may contain sensitive content. Backups are not encrypted, and deletion/redaction does not erase prior backups, immutable audit/history or model context. See [security](SECURITY.md).

## Platforms, installation and migration

macOS arm64/Node22.13.1/pnpm11.6.0 is the observed developer-host environment, with SQLite/FTS5 via the installed native module. Declared Node>=22.13 is not verification of every later ABI. Linux, Windows, Intel macOS, genuinely clean macOS installation and independently rebuilt dependencies are not certified. All five public release profiles remain NO-GO until their required gates pass.

The intended channel is a source-workspace archive, not an npm package or self-contained executable. After a separately authorized release, installation follows [quick start](QUICK_START.md) and [installation](INSTALLATION.md): frozen-lock dependency installation, build, then direct Node CLI/MCP. Source paths refer to the extracted workspace. No global configuration or privileged service is silently installed. Use a reviewed setup dry-run and explicit apply.

No historical released package upgrade is claimed. The database schema is version 11. See [backup/upgrade/downgrade policy](UPGRADE.md); keep verified backup/source artifacts and stop clients before upgrade. Ordinary uninstall retains knowledge, audit and backups. No unrelated config or edited native skill may be overwritten.
